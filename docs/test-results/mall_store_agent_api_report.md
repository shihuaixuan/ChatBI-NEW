- Q3、Q8：问题理解阶段识别出趋势分析或异常分析，但时间校验返回 time_range_unsupported；Agent 随后没有调用语义检索工具，直接回答被运行时守卫拒绝，最终为 sql_failed。
- Q4：问题理解阶段返回 intent_conflict 和 time_range_unsupported；同样未进入语义检索和 SQL 执行，最终为 sql_failed。
- Q6：问题理解已经通过，随后 search_semantic_assets 返回 tool_undeclared_exception；失败发生在语义资产检索工具，不是最终回答阶段，最终为 unexpected_error。
- Q9：问题理解阶段没有产生 question.understood，Run 直接以 INTENT_RECOGNITION_MODEL_CALL_FAILED 失败；步骤数为 0，说明失败发生在 Agent 准备阶段。

1. 接入和数据集绑定：10/10 均完成数据集会话创建，并拿到可关联的 chat_id、record_id、run_id。
2. 问题理解：9/10 产生 question.understood；Q9 在意图识别模型调用阶段失败。
3. 语义检索和 SQL：5/10 进入完整工具链；Q6 进入语义检索但工具异常，Q3/Q4/Q8 因时间校验没有进入工具链。

5. Timeline 和 Trace：10/10 均可读取；失败 Run 的 Trace 节点数量分别为 12、24 或 28，能够区分准备阶段失败、理解校验失败和工具失败。
6. 事件补拉：10/10 通过 after_sequence=0 读取到完整已持久化事件。

## 流程分析口径

1. 接入：检查 /chat/start 和 /chat/agent/stream 是否返回可关联的会话、记录和运行 ID。
2. 产品事件：检查 SSE 的序号、事件域和是否出现 sql.executed、answer.completed。
3. 执行过程：通过 Timeline 统计 Step、Tool Call 和终态错误。
4. 可观测性：通过 Trace 统计节点数量、节点类型和总览状态。
5. 持久化补拉：用 after_sequence=0 补拉事件，检查已发送事件可以被读取。
